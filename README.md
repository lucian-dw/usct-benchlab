# usct-benchlab

[中文](README.zh-CN.md)

A Python library for **sound-speed reconstruction in ultrasound computed
tomography (USCT)**. It connects explicit observations, physical operators,
iterative solvers and evaluation through one case format. It provides numerical
validation within the declared models, not clinical validation.

## Models and algorithms

USCT is an inverse problem constrained by acoustic propagation. For example,

$$
c(x)^{-2}\partial_{tt}p_s-\Delta p_s=q_s,\qquad
d_{sr}=\mathcal M_r p_s+\eta_{sr}.
$$

Different methods retain different parts of these observations:

| Command | Observation | Model / unknown | Configuration |
| --- | --- | --- | --- |
| straight_cgls | Differential ToF, seconds | Straight-ray weighted least squares; $\delta s=1/c-1/c_0$ | [cgls.yaml](configs/algorithms/cgls.yaml) |
| straight_sirt | Differential ToF, seconds | Simultaneous normalized ray updates; $\delta s$ | [sirt.yaml](configs/algorithms/sirt.yaml) |
| straight_sart | Differential ToF, seconds | Ordered-subset normalized ray updates; $\delta s$ | [sart.yaml](configs/algorithms/sart.yaml) |
| bent_ray_gn | First-arrival ToF or water-relative ToF | Native Eikonal/Gauss–Newton; $s=1/c$ | [bent_ray.yaml](configs/algorithms/bent_ray.yaml) |
| rwave_adapter | Complex pressure plus source calibration or water reference | Native fixed/nonlinear WKB or Full-Green Born; $m=1/c^2$ | [rwave.yaml](configs/algorithms/rwave.yaml) |
| fwi_wust | Complex total pressure with explicit conventions | External maintained WUST Helmholtz FWI; $s=1/c$ | [fwi_wust.yaml](configs/algorithms/fwi_wust.yaml) |

The stable command **rwave_adapter** denotes this repository's Ray-Born methods,
not a complete reproduction of upstream r-Wave. See [mathematics](docs/math_formulation.md)
and [algorithms](docs/algorithms.md). YAML files are explicit example overrides,
not calibrated presets or promises of a particular image quality.

## Install and run one case

Python 3.10+:

~~~bash
pip install -e ".[dev,viz]"
usct data prepare --dataset synthetic --out data/synthetic_demo \
  --shape 32 32 --n-transducers 32 --reference-sound-speed-mps 1500
usct run straight_cgls \
  --case data/synthetic_demo/cases/synthetic_circular_sos.h5 \
  --config configs/algorithms/cgls.yaml --out runs/cgls_demo
usct evaluate --run runs/cgls_demo
~~~

This deterministic phantom has no random sampling. Its ToF is generated by the
same straight-ray model used for reconstruction; it is a numerical example,
not a pressure-wave benchmark. [Quickstarts](examples/README.md) and
[usage](docs/usage.md) cover datasets, pressure import and FWI deployment.

## Python and Agent API

~~~python
from usctbench import describe, run
from usctbench.data.synthetic import make_sound_speed_case

spec = describe("straight_cgls")
result = run(
    "straight_cgls",
    make_sound_speed_case(shape=(16, 16), n_transducers=16),
    {"run_controls": {"max_iterations": 10}},
    out="runs/python_demo",
)
print(result.status, result.metrics.get("stop_reason"))
~~~

~~~bash
usct list-algorithms --json
usct describe-algorithm rwave_adapter --variant full_green_nonlinear --json
usct bench --suite configs/benchmarks/synthetic_demo.yaml
~~~

Scientific parameters, run controls and host deployment are separate.
Unknown parameters fail explicitly. Agent permissions come from the static
schema; advanced numerical settings and runtime paths are not autonomous Agent
inputs. See [Agent API](docs/agent_algorithm_api.md).

The public runner prepares each request once; direct low-level calls use
`algorithm.run(case, prepare_config(name, config, case=case))`.
Bent and nonlinear Born share one Gauss-Newton driver with distinct feasible
trial policies. Straight CGLS and fixed Born share bounded projected CG, including
real-model/complex-data gradients. Detailed trial traces require
`diagnostics: true`; default results retain accepted iterations and actual work.

## Inputs and outputs

- Property maps become explicitly labeled model-generated ToF cases.
- Recorded or simulated pressure is imported with its actual geometry, time
  samples, Fourier convention and units. Arrival features are derived explicitly.
- Reconstruction receives no ground truth. GT, if available, is used only for
  image evaluation.
- Image arrays use **[y,x]**, positions and grid spacing use **[y,x]** in meters.
  WUST receives **[x,y]** positions at its protocol boundary.

A run writes **result.h5**, **run.json**, **index.json** on numerical success,
**metrics.json**, and an optional **preview.png**, directly in the requested
output directory. Evaluation/plot failures retain the numerical arrays and their
own failure status. Suite summaries are **benchmark_summary.csv** and
**benchmark_report.md**.

Residuals from ToF and pressure, or different acquisition sources, are not a
single ranking. GT metrics report foreground and full-image regions separately.
Schedule/budget completion is not necessarily numerical convergence.
